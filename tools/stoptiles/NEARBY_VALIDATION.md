# Nearby departure-coverage validation

The widget reads ordinary v1 tiles. Optional service metadata generated by
`--service-metadata` is **not** read by this widget and must remain disabled in
production: recommend setting the GitHub repository variable
`STOP_TILES_SERVICE_METADATA` to `false` through the maintainer's own workflow.
Do not change that variable as part of local validation. Existing v1 tiles and
v2 tiles with extra root keys must both remain readable.

## Reproduce without credentials

Archive the pinned commit to a new directory under `/tmp/opencode`. Copy
`resources/strings/secrets.xml.template` to `secrets.xml` **in that archive
only**, and create a disposable 4096-bit PKCS#8 DER key there. Never copy the
maintainer's key or credentials into a scratch tree. Compile all 37 manifest
devices in normal and test modes sequentially, run
`tools/check_glance_scope.py` for `fr945`, `instinct2` and `fr55`, export
`manifest_beta.xml` from a separate scratch archive and inspect the 80-device
result, per-package settings and debug-string absence. Record foreground and
glance sizes alongside the same profiles built from commit `4263fde`.

Run host `monkeydo -t` for `descentmk1`, `fr645m`, `fr945`, `fenix5`,
`instinct2` and `fr55` only where an isolated simulator is available.
Do not take over a simulator process already running. The host test runner may
exit 1 even after reporting `PASSED (passed=..., failed=0, errors=0)`.
Simulator CPU, heap, storage and Position behaviour are not physical-device
evidence.

Use the read-only fixture-server reference in the sibling
`garmin-christchurch-bus-widget-fakedeps/tools/fakedepartures` directory to
exercise shared/opposite/short-turn, empty, malformed and delayed responses
for **multiple** stop codes. Supply only a disposable subscription key.
The busy payload is about 43 KB for one stop; eight such responses may be
received per 10-second request cycle. Do not call the real endpoint with a
real key during this exercise.

## Hardware gate: pending

Repeat the busy-cluster test on a real Descent Mk1 (firmware and Connect IQ
version recorded), with a real-size tile and measured callback times, cache
capacity and free heap. A previous beta crashed with a CPU watchdog on a
real Mk1. No simulator pass alone resolves this gate. Test page retention
until Select, favourites (including equal-distance), counts 1, 3 and 5,
more than 100 m movement, stale/offline recovery, no-data/error responses,
and no repeated work in refresh callbacks. Copy `CIQ_LOG.YML` and `.BAK`
before another crash overwrites them. A glance is not available on Mk1.

## Human-only beta

Pin the final reviewed commit, then use the normal private real-key and Metro
credential workflow in a separate checkout. Keep the beta manifest identity
and increment the beta store version for each upload. Verify phone settings
independently of sideloaded defaults. Neither a local build nor a passing
simulator run authorises publication.
